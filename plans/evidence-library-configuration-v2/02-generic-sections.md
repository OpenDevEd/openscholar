# Plan 02 — Generic sections (OpenScholar)

Lane A. Branch off `origin/dev` after the contract re-pin from plan 01.

## Goal

Any owner-edited section from the registry can be saved, frozen and
assembled without adding code per section.

## Scope

1. Replace `essentialConfigurationSectionsValidator` and the four
   hand-written section validators with `sectionRowValidator = v.object({ sectionKey: sectionKeyValidator, payload: v.any() })`
   at the Convex boundary. Payloads are validated in the mutation with a
   per-section precompiled validator generated by `contract-sync.mjs`
   (one AJV validator per registry section, from the schema slice at the
   section pointer, plus the full validator that already exists).
2. `saveEvidenceLibraryDraftSections({ libraryId, expectedEditVersion, sections })`
   becomes the only save mutation: validates each payload, rejects write-only
   pointers (`assertNoCredentialMaterial`), enforces the size budgets, writes
   the rows, bumps `editVersion`. Delete `saveEssentialEvidenceLibraryConfiguration`.
3. Activation freezes every draft row (no `sectionKeys` list).
4. Assembly: `assembleEvidenceLibraryConfiguration({ sections: Record<sectionKey, payload>, managed })`
   merges all owner sections over schema defaults, then platform values
   (`services`, `authentication`, `search.embedder`), then per-group Zotero keys
   (plan 07 fills them; plan 02 leaves a typed hook `applySourceCredentials`).
5. Hand-written rules kept in `essential-configuration.ts` → rename to
   `owner-rules.ts`: `identity.baseUrl` must equal the binding's base URL;
   `footer.poweredBy` must be `true`.
6. Assembly failures at deploy time are stored on the operation as
   `issues: [{ pointer, message }]` and exposed by `getDraft` /
   `getLibrary` so the page can list them (plan 05 renders them).
7. Delete the 18 hand-written enumerations listed in the fact-finding report
   (validators, TS types, assembly literal, mutation args, freeze list,
   form-contract field map, shell maps). Keep `form-contract.ts` but make it
   generic: `readStringContract(pointer)`, `readEnum(pointer)`, `readNumber(pointer)`.
8. Library creation seeds `identity` and `localization` rows only; every other
   section is absent until saved (absent = schema defaults).

## Tests

- `contract-sync.test.ts`: one validator per registry section is emitted and
  compiled; the section slice validator rejects an unknown key.
- `drafts.test.ts`: saving `navigation` and `footer` rows round-trips;
  a payload that breaks its slice is rejected with a pointer; write-only
  pointer rejected; edit-version conflict.
- `validation.test.ts` (assembly): a manifest with identity, theme, footer,
  navigation, filters, features saved passes the full validator; sections not
  saved come from defaults; `poweredBy: false` is rejected by owner rules.
- `operations.test.ts`: assembly failure stores issues on the operation.
- Delete tests that only covered the removed four-section shape.

## Deployability gate

`npx convex dev --once` on the lane deployment ends with
`Convex functions ready!`; `npx convex logs --history 200` shows no error;
`npm run dev:web` on port 3011: the existing configuration page (still the
old shell until plan 05) saves and activates a library on the lane.

## Completion

PR to `dev`. The PR description lists the removed enumerations. Old
development drafts are simply re-saved by the new page later.

## Risks

- Convex function argument size: sending all sections at once stays under the
  768 KB draft budget already enforced.
- The precompiled validator bundle grows (24 validators). Measure the `.cjs`
  size; if it passes 1 MB, generate one validator that takes `(sectionKey, payload)`.

## Deviations (2026-08-26, lane A)

1. **Started from current `origin/dev`, not after plan 01.** Decided by the
   integration owner. The contract is pinned at new-el `c353b55b`. Plan 01's
   re-pin only regenerates the same artifact files with the same generator.
2. **Two lane C files get a call-site edit.** The deployability gate says the
   old shell must still save and activate on the lane. Deleting
   `saveEssentialConfiguration`, `EssentialConfigurationSections` and the
   form-contract field map breaks the shell's and page's imports, so
   `components/evidence-libraries/configuration/evidence-library-configuration-shell.tsx`
   and `app/evidence-libraries/[libraryId]/configuration/page.tsx` are changed
   only where they call the removed code: the shell keeps its four-section
   form type locally and sends `{ sectionKey, payload }` rows to
   `saveDraftSections`; the page builds its field map from the generic
   `readStringContract` and `readEnum` readers. Plan 05 replaces both files.
3. **Activation checks the schema's required sections.** Assembly runs in a
   Node action after the setup pipeline has already created the database, and
   a failed setup operation cannot be re-activated. So activation also
   rejects a draft that lacks a section the schema marks `required`
   (`identity`, `theme`, `localization`, read from the schema, not written by
   hand). Everything else still goes through the full validator at assembly
   and is stored as `issues` on the operation.
4. **`getLibrary` does not exist.** `getDraft` returns the library's latest
   operation (with `issues`) as `operation`; `getSetupDraft` already returns
   the setup operation, which carries the same field.
