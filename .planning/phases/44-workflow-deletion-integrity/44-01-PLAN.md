<objective>
Fix `cancelExtraction` to actually stop workflow processing and protect credits.

Purpose: Currently, cancelling a job only patches the status to "cancelled" but never calls `workflow.cancel()` or `pdfProcessingPool.cancelAll()`. In-flight workpool actions continue processing papers and deducting credits after cancellation. This wastes compute and bills users for work done after they cancelled.

Output: Updated `cancelExtraction` mutation that stops the workflow and workpool, plus credit-guard checks in both `downloadAndIndexPdfAction` and `waitAndExtractAction` that skip credit deduction for cancelled jobs.
</objective>

  args: { jobId: v.id("extractionJobs") },
  returns: v.object({ success: v.boolean() }),

    requireExtractionEnabled();
    const user = await requireAuth(ctx);
    const job = await ctx.db.get(args.jobId);
    if (!job || job.userId !== user._id) {
      throw createError("NOT_FOUND", "Job not found");

    if (["completed", "failed", "cancelled"].includes(job.status)) {
       return { success: true };
    }
    await ctx.db.patch(args.jobId, {
      status: "cancelled",
      updatedAt: Date.now(),
    });
    return { success: true };
  },
});

Restructure the existing `if (embeddingCreditsToDeduct > 0)` into an else-if so the guard check wraps it.

**Guard 2 -- waitAndExtractAction (LLM extraction credits):**
This is trickier because `withUserCreditsBatch` wraps the entire extraction call. The guard must be BEFORE `withUserCreditsBatch` is called (~line 983). Add a fresh job status check:

```typescript
// Credit guard: skip extraction credit deduction if job was cancelled
const freshJobForCredits = await ctx.runQuery(
  internal.extraction.queries.getJobInternal,
  { jobId: args.jobId }
);
if (freshJobForCredits?.status === "cancelled") {
  console.log(`[creditGuard] Skipping extraction credit deduction - job ${args.jobId} cancelled`);
  // Return results without billing -- extraction work was done but job is cancelled
  // Still need to return a valid shape so onComplete can handle gracefully
  return {
    success: true,
    results: [],
    creditsUsed: 0,
    pdfContentUsed: false,
  };
}
```

Place this guard immediately before the `const extracted = await withUserCreditsBatch(...)` call. If the job is cancelled, return early with empty results and zero credits. This is safe because the onComplete handler checks for cancellation via the workpool "canceled" kind.

Note: There is an inherent race window where 0-2 papers may still be billed between the cancel click and the guard check. This is documented as expected behavior per the research's open question and STATE.md blocker note. The guard is placed as close to the deduction call as possible to minimize this window.
