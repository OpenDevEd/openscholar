**File 2: convex/webhooks/clerk.ts**

**Change 2 — Deserialize data in clerkWebhook httpAction (line 105):**
After line 105 (`const { eventId, eventType, data } = result;`), the `data` is now a JSON string. Parse it before passing to `processClerkWebhookEvent`.

Change lines 105-112 from:
```typescript
const { eventId, eventType, data } = result;
const outcome = await processClerkWebhookEvent({
  eventId,
  eventType,
  data,
  runMutation: (mutation, mutationArgs) =>
    ctx.runMutation(mutation as never, mutationArgs as never),
});
```

To:
```typescript
const { eventId, eventType, data } = result;
const parsedData: unknown = JSON.parse(data);
const outcome = await processClerkWebhookEvent({
  eventId,
  eventType,
  data: parsedData,
  runMutation: (mutation, mutationArgs) =>
    ctx.runMutation(mutation as never, mutationArgs as never),
});
```

The `parsedData` variable is explicitly typed as `unknown` to match `processClerkWebhookEvent`'s parameter type. The `processClerkWebhookEvent` function and `parseClerkUserPayload` both expect `data: unknown` and perform their own runtime checks, so no further changes are needed in those functions.

**Why this is safe:**
1. `JSON.stringify` then `JSON.parse` is a lossless roundtrip for any JSON-compatible value (which Clerk webhook data is — it comes from `webhook.verify()` which returns parsed JSON).
2. The consumer (`processClerkWebhookEvent` → `parseClerkUserPayload`) already treats data as `unknown` and does runtime type checks (`typeof data !== "object"`, `typeof candidate.id !== "string"`), so receiving parsed JSON is functionally identical.
3. No behavioral change to the webhook flow — same data reaches the same consumers.

**What NOT to change:**
- Do NOT change `processClerkWebhookEvent`'s parameter type — it stays `data: unknown`
- Do NOT change `parseClerkUserPayload`'s parameter type — it stays `data: unknown`
- Do NOT change any test files — the unit function `verifyClerkWebhookPayload` is tested directly and will now return a string `data` field, which is the correct new behavior

**After changes:** Run `npx tsc --noEmit` to verify no type errors. The only expected change is that `ClerkWebhookVerificationSuccess.data` is now `string` instead of `unknown`, which is a narrowing (more specific), so any code that accepted `unknown` will also accept `string`.
