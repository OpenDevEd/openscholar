Extend the existing `convex/extraction/cascade-delete.test.ts` with a new `describe("partial-failure recovery (TEST-04)")` block.

**Approach:** The cascade delete function uses `scheduler.runAfter(0, ...)` to re-schedule itself. In convex-test, use `t.finishAllScheduledFunctions(vi.runAllTimers.bind(vi))` to execute all scheduled iterations until completion.

**Test 1 -- Partial deletion recovery:**
1. Seed a full job graph via `seedFullJobGraph(t)`
2. Manually delete ONLY the `extractionEvidenceUnits` records (simulating step 1 completion)
3. Call `deleteExtractionInternal` -- it should skip step 1 (no evidence units) and proceed through steps 2-9
4. Use `t.finishAllScheduledFunctions(vi.runAllTimers.bind(vi))` to complete all scheduled batches
5. Verify all child tables are empty for this jobId

**Test 2 -- Complete deletion verification:**
1. Seed a full job graph
2. Run `deleteExtractionInternal` with `t.finishAllScheduledFunctions`
3. Query every child table by jobId and paperId -- all should return empty arrays
4. The job record itself should be deleted

**Test 3 -- Idempotent re-invocation:**
1. Seed a full job graph
2. Run deleteExtractionInternal to completion
3. Run deleteExtractionInternal again on the same jobId
4. Should complete without errors (the job is already gone, `ctx.db.get(jobId)` returns null, step 9 does nothing)

Use `vi.useFakeTimers()` / `vi.useRealTimers()` pattern from the existing test file for scheduled function execution.
