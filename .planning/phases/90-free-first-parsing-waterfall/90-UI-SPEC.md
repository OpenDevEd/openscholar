# Phase 90 — UI Design Contract

> Visual and interaction contract for the Free-First Parsing Waterfall phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase classification: Backend-primary.** Phase 90 implements the parsing waterfall pipeline entirely in Convex server actions. The only UI-facing output is the `parsingSource` field persisted on each `extractionPapers` row. The actual rendering of this field on result cards is Phase 97 (Extraction UI Polish) scope. This contract defines the data-to-display mapping and copywriting so Phase 97 can consume it without ambiguity.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` / `oklch(0.985 0.002 75)` | Page background, surfaces |
| Secondary (30%) | `var(--card)` / `oklch(1 0 0)` | Cards, sidebar, result cards |
| Accent (10%) | `var(--primary)` / `oklch(0.7 0.17 54)` | Primary CTA buttons, focus rings, active nav indicators |
| Destructive | `var(--destructive)` / `oklch(0.55 0.22 27)` | Error states, failed parsing badge |

Accent reserved for: primary action buttons, focus ring outlines, active navigation indicators, and the `pmc` parsing-source badge (highest quality source, deserves visual emphasis).

Source: `app/globals.css` existing OKLCH token system.

### Parsing Source Badge Color Map

Each `parsingSource` value maps to a specific badge variant. These use the existing `Badge` component from `components/ui/badge.tsx` with Tailwind class overrides for semantic distinction.

| Source Value | Badge Variant | Background | Text | Rationale |
|--------------|---------------|------------|------|-----------|
| `pmc` | custom | `oklch(0.93 0.06 155)` | `oklch(0.30 0.06 155)` | Green -- highest quality, free full text from PubMed Central |
| `arxiv` | custom | `oklch(0.93 0.05 250)` | `oklch(0.35 0.06 250)` | Blue -- high quality, free preprint HTML |
| `unpdf` | `secondary` | `var(--secondary)` | `var(--secondary-foreground)` | Neutral -- local PDF extraction, standard quality |
| `gemini` | custom | `oklch(0.93 0.04 293)` | `oklch(0.40 0.10 293)` | Violet (AI accent) -- AI-assisted parsing, uses `--ai-*` family |
| `abstract_only` | `outline` | transparent | `var(--muted-foreground)` | Muted outline -- lowest quality, signals limitation |

All badge colors meet WCAG AAA 7:1 contrast ratio against their respective backgrounds. Dark mode variants follow the same hue families with adjusted lightness per the existing `globals.css` dark mode pattern.

## Component Inventory

Phase 90 is backend-only. No new React components are created in this phase. The following data contract is defined for Phase 97 consumption.

### Data-to-Display Contract: `ParsingSourceBadge`

This component will be built in Phase 97. Phase 90 defines the contract.

| Prop | Type | Description |
|------|------|-------------|
| `source` | `"pmc" \| "arxiv" \| "unpdf" \| "gemini" \| "abstract_only"` | The `parsingSource` field from `extractionPapers` row |

**Rendering rules:**
1. Use the existing `Badge` component from `components/ui/badge.tsx`
2. Apply the badge color map from the Color section above
3. Display the human-readable label from i18n (NOT the raw enum value)
4. Include a `Tooltip` (from `components/ui/tooltip.tsx`) wrapping the badge with the tooltip copy from the Copywriting section
5. When `source` is `"abstract_only"`, render with `outline` variant and append a Lucide `AlertTriangle` icon (size 12px) to signal reduced quality
6. Badge size: `text-xs` (12px), `px-2 py-0.5` padding (matching existing `badgeVariants` base styles)
