5. **Replace the `handleRatingChange` function body.** The new logic:
```typescript
const handleRatingChange = (rating: string) => {
  const previousRating = ratings[paperId];
  const newRating = rating === "no-rating" ? null : parseInt(rating);

  // 1. ALWAYS update Zustand (optimistic, localStorage) -- unconditional
  if (rating === "no-rating") {
    setRating(paperId, null);
  } else {
    setRating(paperId, parseInt(rating));
  }

  // 2. If signed-in AND we have paper data AND rating is not removal, save to Convex
  if (phase === "authenticated" && paperResult && newRating !== null) {
    const trimmed = trimPaperData(paperResult);
    saveToLibrary({
      ...trimmed,
      rating: newRating,
    }).catch((error) => {
      // Log but don't block -- Zustand already has the rating
      console.error("[Library] Failed to save to library:", error);
    });
  }

  // 3. PostHog tracking (existing, unchanged)
  posthog.capture("paper_rated", {
    paper_id: paperId,
    rating: newRating,
    previous_rating: previousRating ?? null,
    is_rating_removed: rating === "no-rating",
    variant: variant,
  });
};
```

**Critical behavioral rules:**
- Zustand `setRating` is ALWAYS called first (step 1) -- this is unconditional for both anonymous and signed-in users.
- Convex mutation is fire-and-forget (`.catch()` logs but does not throw) -- the rating UI is optimistic.
- Rating removal (`"no-rating"`) does NOT call the mutation. Library removal is a separate Phase 23 action (LIB-07).
- `paperResult` is optional -- components that don't pass it gracefully degrade to Zustand-only.
- `trimPaperData` is called client-side to avoid sending the full Work blob over the wire.

**Do NOT change** the JSX/render portions of the component. Only the imports, props interface, hooks, and `handleRatingChange` function change.
