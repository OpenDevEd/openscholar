## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> createExtractionJob mutation | Untrusted paper count crosses from browser to Convex mutation |
| Convex mutation -> client catch block | Error data flows back to browser for toast rendering |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-100-03 | Tampering | createExtractionJob paper count | mitigate | Server-side `getExtractionLimitForUser(ctx, user._id)` check rejects over-limit submissions regardless of client-side validation. The limit is derived from the user's subscription, not from client input. |
| T-100-04 | Information Disclosure | EXTRACTION_LIMIT_EXCEEDED error message | accept | The error message reveals the user's own paper limit (currently 1000 for all tiers). This is not sensitive -- the limit is displayed in the UI at multiple points. No other user's data is exposed. |
| T-100-05 | Spoofing | Error code in catch block | accept | The error code is read from a ConvexError thrown by the Convex runtime. A malicious client cannot forge the error code because the mutation runs server-side. The client only reads the code for toast routing. |
</threat_model>
