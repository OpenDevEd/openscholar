# Phase 100 — UI Design Contract

> Visual and interaction contract for Phase 100: Backend Wiring + TierSelector Fix. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Phase Classification

**This is a backend-dominant phase.** Phase 100 ships Convex actions (`resolveManualIds`, `resolveByDoi`), the `createCascadeTiers(tier)` cascade filter, the `EXTRACTION_LIMIT_EXCEEDED` server-side hard reject, and the 5-edit TierSelector threading. The UI surface is limited to two modifications in existing components:

1. **`extraction-dialog.tsx`** -- pass `tier` to the `createJob` mutation call (line 125) and migrate inline string-matching error handling (lines 135-147) to the standard `resolveToastError` pattern.
2. **Error toast for `EXTRACTION_LIMIT_EXCEEDED`** -- a new i18n key rendered by the existing `showStyledToast("error", ...)` component with no visual changes to the toast itself.

No new components are created. No new pages are created. No layout changes are required. The existing design system tokens, spacing, typography, and color contracts apply unchanged.

| Toast title | "Paper limit reached" | `common.extractionLimitExceeded` |

## Interaction Contracts

### 1. TierSelector Threading (D-01, D-02)

**Before:** User selects a tier in `TierSelector`, the value is captured in local state, PostHog receives it, but `createJob()` does not send it to the backend.

**After:** User selects a tier, and the `createJob()` call includes `{ papers, questions, tier }`. The mutation persists `tier` on the job row. No visual change to the TierSelector component.

**Interaction unchanged:** RadioGroup with 3 options (auto/cheap/accurate). Selected state: `border-primary/50 bg-primary/5`. Hover state: `bg-accent/30`. No animation changes.

### 2. Error Handling Migration (D-09)

**Before:** `extraction-dialog.tsx` catches errors inline with string matching for `EXTRACTION_JOB_ALREADY_ACTIVE` (lines 135-147) and falls back to `getErrorMessage` for everything else.

**After:** All errors go through `resolveToastError`. The `MESSAGE_KEY_BY_CODE` map handles routing to the correct i18n key. `EXTRACTION_LIMIT_EXCEEDED` is a new entry. `EXTRACTION_JOB_ALREADY_ACTIVE` uses its existing key.

**Toast visual contract:** Uses existing `showStyledToast("error", title, { description })`. Red gradient bar on the left. `AlertCircle` icon. Close button appears on hover. 4-second auto-dismiss. No visual changes to the toast component.

### 3. Server-Side Hard Reject (LIM-07)

**Trigger:** User submits a job with more papers than their tier allows (client-side basket should prevent this, but the server reject is the safety net).

**Error flow:** `createExtractionJob` throws `ConvexError({ code: "EXTRACTION_LIMIT_EXCEEDED", message: "..." })` --> client `resolveToastError` reads `code` --> maps to `extractionLimitExceeded` --> renders localized toast with `{limit}` and `{excess}` interpolation.

**No loading state change:** The "Starting..." spinner reverts to "Start Extraction" after the error. The dialog stays open. Existing `finally { setIsSubmitting(false) }` handles this.
