## Spacing Scale

Declared values (multiples of 4 only, aligned with existing codebase patterns):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`gap-1`, `p-1`) | Icon-to-label gaps inside badges, toggle group button internal padding |
| sm | 8px (`gap-2`, `p-2`) | Table cell padding (`TableCell` default), filter control gaps, toolbar item spacing |
| md | 16px (`gap-4`, `px-4`) | FilterSection horizontal padding (existing: `px-4`), toolbar section gaps |
| lg | 24px (`gap-6`, `py-6`) | Toolbar top/bottom breathing room within the shell |
| xl | 32px (`gap-8`) | Gap between the toolbar and the view area beneath it |

Exceptions: none. The 44px touch target minimum does not apply in this phase (no mobile-specific touch targets; Phase 105 handles responsive touch targets).

**Source:** Existing FilterSection uses `px-4 pt-3 pb-2` (header) and `pb-4` (content). Table primitive uses `p-2` cells. These are the spacing anchors.

## Typography

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|---------------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.43 (20px) | Table cell text, filter dropdown option text, column visibility checkbox labels |
| Label | 14px (`text-sm`) | 600 (semibold) | 1.43 (20px) | FilterSection title, toolbar section labels, table header text, badge text inside table cells (`StatusBadge`/`ConfidenceBadge`) |
| Heading | 16px (`text-base`) | 600 (semibold) | 1.5 (24px) | WorkbenchShell header (job title above toolbar) -- rendered by Phase 103 but the shell reserves this slot |

**Weights used:** 400 (regular) and 600 (semibold). Two-weight system: regular for body text, semibold for all emphasis roles (labels, table headers, badges, headings). All instances of `font-medium` (weight 500) in this phase are replaced with `font-semibold` (weight 600) to maintain a clean two-weight hierarchy.

**Font:** Outfit variable weight (already loaded via `next/font/google` in `app/layout.tsx`).

**Source:** Existing badges use `text-xs font-semibold`. Existing `TableHead` uses `font-medium` -- this phase upgrades table headers to `font-semibold` for two-weight consistency. Existing `TableCell` and `TableCaption` use `text-sm` at regular weight.

**Migration note:** The shadcn `TableHead` primitive defaults to `font-medium`. Implementors must override with `font-semibold` in the `WorkbenchDataTable` header cells to match this contract. The `FilterSection` title text similarly changes from `font-medium` to `font-semibold` within toolbar usage (the shared component itself is not modified -- the override is applied at the toolbar composition level via className).

## Interaction Contracts

### Toolbar Filter Groups

Each filter group is wrapped in `FilterSection` and behaves identically:

| Filter | Control | Options | FilterFn | Clear Behavior |
|--------|---------|---------|----------|----------------|
| Status | `Select` | `pending`, `parsing`, `extracting`, `completed`, `failed`, `cancelled` | `"equals"` | Removes the column filter entry, `isActive` becomes false, orange bar disappears |
| Confidence | `Select` | `high`, `medium`, `low` | `"equals"` | Same |
| Year | `Input` (type text, placeholder "e.g. 2020-2024") | Free text | Custom range parser | Same |
| Venue | `Input` (type text, placeholder) | Free text | `"includesString"` | Same |
| Answer (per-question) | `Input` (type text) | Free text, one per dynamic question column | `"includesString"` | Same |

**FilterSection `isActive` derivation:** `isActive = columnFilters.some(f => f.id === columnId && f.value !== "" && f.value !== undefined)`.

### Sort Interaction

- Click a sortable table header to toggle sort: none -> ascending -> descending -> none.
- Active sort column header renders the direction icon (`ArrowUp` or `ArrowDown`, 14px) in `text-primary`.
- Inactive sortable headers render `ArrowUpDown` icon (14px) in `text-muted-foreground` on hover only.
- Multi-sort is NOT supported (single column sort only). This matches TanStack Table's default `enableMultiSort: false`.

### Column Visibility Toggle

- Click the `Settings2` button in the toolbar to open the popover.
- "Toggle all" checkbox at top: checked = all visible, indeterminate = some hidden, unchecked = all hidden.
- Each column checkbox: checked = visible, unchecked = hidden.
- The `title` column cannot be hidden (`enableHiding: false` on the column definition).
- Changes immediately update the Zustand store and the table instance.

### View Switcher

- Three icon buttons in a segmented control: Table (`Table2`), Card (`LayoutGrid`), Split (`Columns`).
- Active view has `bg-background text-primary shadow-sm` styling.
- Switching views persists to the Zustand store (`localStorage`).
- View transitions use `subtleSpring` from `lib/animation-config.ts`: `stiffness: 350, damping: 30, mass: 0.8`.
- Transition: outgoing view fades out (`opacity: 0`, 150ms), incoming view fades in (`opacity: 0 -> 1, y: 8 -> 0`, `subtleSpring`).

### Hydration Guard

- Until `_hasHydrated` is `true` on the Zustand store, the shell renders a skeleton placeholder (a `div` with `bg-muted/50 animate-pulse rounded-lg h-8 w-full` for the toolbar area).
- This prevents the flash where column visibility and active view snap from defaults to stored values.

## Copywriting Contract

This phase ships primitives only (no routes, no data fetching, no user-facing pages). Copywriting is minimal and confined to toolbar labels and filter names. All strings go through `useTranslations("extraction")`.

| Element | i18n Key | en-US Copy |
|---------|----------|------------|
| View: Table | `workbench.viewTable` | `Table` |
| View: Card | `workbench.viewCard` | `Cards` |
| View: Split | `workbench.viewSplit` | `Split` |
| Column visibility button tooltip | `workbench.columns` | `Columns` |
| Column visibility "toggle all" | `workbench.toggleAll` | `Toggle all` |
| Filter: Status | `workbench.filterStatus` | `Status` |
| Filter: Confidence | `workbench.filterConfidence` | `Confidence` |
| Filter: Year | `workbench.filterYear` | `Year` |
| Filter: Venue | `workbench.filterVenue` | `Venue` |
| Filter: Answer | `workbench.filterAnswer` | `Answer` |
| Year input placeholder | `workbench.yearPlaceholder` | `e.g. 2020-2024` |
| Venue input placeholder | `workbench.venuePlaceholder` | `Filter by venue...` |
| Answer input placeholder | `workbench.answerPlaceholder` | `Filter answers...` |
| Empty table body (no rows after filter) | `workbench.noResults` | `No papers match the current filters. Try adjusting or clearing filters.` |
| Empty table body (no data loaded) | `workbench.noData` | `No extraction results to display.` |

**No primary CTA** in this phase. The primary CTA ("Review & start extraction") belongs to the basket drawer (Phase 99/102).

**No destructive actions** in this phase. Filter clearing is non-destructive (data is never mutated).

**No error states** in this phase. Data fetching errors are Phase 103's responsibility.
