## Copywriting Contract

### Error Boundary (CRASH-01)

Both `app/results/error.tsx` and `app/settings/error.tsx` use **identical copy** from existing i18n keys. No new keys needed.

| Element | i18n Key | en-US Copy |
|---------|----------|------------|
| Heading | `common.somethingWentWrong` | "Something went wrong" |
| Description | `errors.unexpectedIssue` | "We hit an unexpected issue. Please retry, or return to a stable page." |
| Primary CTA | `common.retry` | "Retry" |
| Secondary CTA | `common.goHome` | "Go Home" |

Icon: `AlertTriangle` from lucide at 32px (`h-8 w-8`), colored `text-muted-foreground`.

### Mutation Rejection Toasts (CRASH-04)

All four mutation rejection sites route through the existing `showStyledToast("error", ...)` + `resolveToastError()` pipeline. The error-resolver maps Convex error codes to existing i18n toast keys. No new toast copy is needed.

| Call Site | Error Resolution |
|-----------|-----------------|
| `rating-selector.tsx` (saveToLibrary/removeFromLibrary) | `resolveToastError(err, t("toast.unexpectedError"))` |
| `focus-mode.tsx` (saveToLibrary/removeFromLibrary) | `resolveToastError(err, t("toast.unexpectedError"))` |
| `library-page-client.tsx` (removeItem) | `resolveToastError(err, t("toast.unexpectedError"))` |
| `settings/connections/page.tsx` (revokeKey) | `resolveToastError(err, t("toast.unexpectedError"))` |

The fallback copy for unrecognized errors: **"An unexpected error occurred. Please try again."** (existing `toast.unexpectedError` key).

### Empty State

Not applicable. This phase creates no new pages or data views.

### Destructive Confirmation

Not applicable. This phase modifies existing mutation call sites but adds no new destructive actions. The mutations that need toast routing (save/remove from library, revoke API key) already have their own confirmation flows.

## Interaction Contract

### Error Boundary Behavior

| Trigger | Response | Animation |
|---------|----------|-----------|
| Unhandled error in results route | Show error card within results layout (sidebar stays visible) | None (instant render) |
| Unhandled error in settings route | Show error card within settings layout (sidebar stays visible) | None (instant render) |
| User clicks "Retry" | Calls Next.js `reset()` to re-render the route segment | None |
| User clicks "Go Home" | Navigates to `/` via Next.js Link | Standard page transition |

### Toast Behavior (existing system, no changes)

| Trigger | Response | Duration |
|---------|----------|----------|
| Mutation rejection | `showStyledToast("error", ...)` appears bottom-right | 4000ms (existing default) |
| User hovers toast | Close button appears (opacity transition, existing) | Persists while hovered |
| User clicks close | Toast dismisses | 200ms fade (existing) |

### Clerk Visibility Retry (invisible)

| Trigger | Response | Visual Feedback |
|---------|----------|-----------------|
| Tab becomes visible after being hidden | `retryUserSync()` fires (5s cooldown) | None (silent background retry) |

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Error boundary focus management | Focus moves to the error card heading when the boundary catches. Use `tabIndex={-1}` + `ref.focus()` on the heading element. |
| Error boundary screen reader | Error card uses `role="alert"` so screen readers announce the error immediately. |
| Toast announcements | Existing Sonner toaster already uses `aria-live="polite"` region. No changes needed. |
| Retry button | Standard shadcn Button with built-in focus ring (`focus-visible:ring-2 ring-ring`). |
| Contrast | All text meets WCAG AAA (7:1). Heading on card: foreground oklch(0.2) on card oklch(1) = contrast > 15:1. Muted text: oklch(0.55) on oklch(1) = contrast > 4.5:1 minimum (AA). |
| Reduced motion | Error boundaries use no animation. Toast transitions respect `prefers-reduced-motion` via existing Sonner configuration. |
