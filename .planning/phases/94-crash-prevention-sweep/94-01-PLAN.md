**CRASH-03: Clerk visibility-change retry (per D-09, D-10, D-11)**

In `components/providers/convex-provider.tsx`, add a new `useEffect` inside `AuthReadinessProvider`, immediately after the `retryUserSync` definition (after line 217, before the `contextValue` memo). The effect:

```tsx
// Retry auth sync when user returns to a stale tab (CRASH-03, per D-09)
useEffect(() => {
  let lastRetryTimestamp = Date.now(); // Initialize to now to skip first fire (Pitfall 3)
  const COOLDOWN_MS = 5000; // 5-second cooldown per D-10

  const handleVisibilityChange = () => {
    if (document.visibilityState !== "visible") return;
    const now = Date.now();
    if (now - lastRetryTimestamp < COOLDOWN_MS) return;
    lastRetryTimestamp = now;
    retryUserSync();
  };

  document.addEventListener("visibilitychange", handleVisibilityChange);
  return () => {
    document.removeEventListener("visibilitychange", handleVisibilityChange);
  };
}, [retryUserSync]);
```

Key details:
- `lastRetryTimestamp` initializes to `Date.now()` (not 0) to skip the initial page-load visibility event per Pitfall 3 from RESEARCH.md
- Depends only on `retryUserSync` -- that callback already guards on `isAuthenticated`
- Cleanup removes the listener per D-11

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-94-01 | Denial of Service | Visibility retry | mitigate | 5-second cooldown on retryUserSync calls prevents rapid-fire auth mutations on quick tab switches (D-10). `lastRetryTimestamp` initialized to `Date.now()` to skip initial page-load fire (Pitfall 3). |
| T-94-02 | Information Disclosure | Error boundary | mitigate | Error boundaries use i18n generic messages ("Something went wrong") -- never expose stack traces or internal error details to the user. `console.error` logs full error for developers only. |
