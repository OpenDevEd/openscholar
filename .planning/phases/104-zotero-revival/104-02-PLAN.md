// Handle Zotero OAuth callback query params (D-03)
// The callback redirects to /?zotero_connected=true or /?zotero_error=...
// We handle it here because users navigate to settings after OAuth
useEffect(() => {
  const params = new URLSearchParams(window.location.search);
  const connected = params.get("zotero_connected");
  const error = params.get("zotero_error");

  if (connected === "true") {
    toast.success(t("zotero.oauthSuccess"));
  } else if (error) {
    toast.error(t("zotero.oauthError", { error }));
  }

  if (connected || error) {
    window.history.replaceState({}, "", window.location.pathname);
  }
}, []); // eslint-disable-line react-hooks/exhaustive-deps

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Convex startOAuth action | User initiates OAuth, action generates HMAC-SHA1 signature server-side. Callback URL from client is validated by Zotero (must match registered app). |
| Zotero OAuth -> Convex HTTP callback | External redirect carries oauth_token + oauth_verifier. Token verified server-side against stored tokenSecret. |
| Browser -> Convex disconnect mutation | Auth-gated via `requireAuth(ctx)` -- only the authenticated user's own connection is deleted. |
| Browser query params (callback) | User-controllable URL params (`?zotero_connected=true`, `?zotero_error=...`). Only used for toast display, no security-sensitive action taken based on these params. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-104-04 | Spoofing | OAuth callback URL | mitigate | Callback URL constructed from `window.location.origin` (same-origin); Zotero validates against registered app callback URL; token verified server-side via stored `tokenSecret` in `completeOAuth` |
| T-104-05 | Tampering | Query param toast | accept | `?zotero_connected=true` only triggers a toast (no state change). Worst case: user sees a false success toast. The reactive `getConnectionStatus` query is the source of truth for UI state. |
| T-104-06 | Information Disclosure | ZoteroConnectionCard | mitigate | Card displays username and zoteroUserId (non-sensitive identifiers). Encrypted API key is never exposed to client -- `getConnectionStatus` query does not return it. |
| T-104-07 | Elevation of Privilege | disconnect mutation | mitigate | Gated by `requireAuth(ctx)` -- only deletes the calling user's connection, not other users'. |
</threat_model>
