## Component Inventory

### 1. EvidenceQuote

**Purpose:** Renders the verbatim text slice from `bodyText.slice(evidenceStartChar, evidenceEndChar)`. NEVER renders the LLM's `evidenceQuote` field.

**Props:**
```typescript
interface EvidenceQuoteProps {
  paperId: Id<"extractionPapers">;
  startChar: number;
  endChar: number;
}
```

**States:**

| State | Visual Treatment |
|-------|-----------------|
| Loading | Skeleton pulse placeholder, 3 lines at 14px height, `rounded-md`, `bg-muted animate-pulse` |
| Loaded | Quote text in `text-sm` (14px) weight 400, line-height 1.43. Left border 3px solid `var(--primary)` at 40% opacity. Background `var(--pdf-highlight)`. Padding: 8px 16px. Border-radius: `var(--radius-md)`. |
| Error (paper not found) | Inline text: "Evidence unavailable" in `text-sm text-muted-foreground`. No card, no border. Lucide `AlertCircle` icon at 16px, `text-muted-foreground`. |
| Error (out-of-bounds chars) | Same as "paper not found" treatment. |
| Empty (start === end or undefined) | Not rendered. Parent component hides the evidence block entirely. |

**Interactions:**
- Entire quote block is clickable (cursor: pointer). Click navigates to the paper's source view with the character range highlighted.
- Hover: background transitions to `var(--pdf-highlight)` at 30% opacity (from 22%). Transition: 150ms ease.
- Focus-visible: `outline: 2px solid var(--ring)`, `outline-offset: 2px`.

**Data fetching:** Dedicated Convex query for paper `bodyText` by paperId. Does NOT piggyback on a heavier paper-detail query -- the bodyText field can be large and should be fetched independently with a focused query returning only `bodyText`.

### 2. InsufficientEvidenceCard

**Purpose:** Displayed when `answer === "insufficient_evidence"`. A valid extraction outcome, NOT an error.

**Visual Treatment:**
- Uses existing `Card` component with additional classes: `opacity-75 border-dashed`.
- No evidence block rendered (no `EvidenceQuote`).
- Card header: question text in `text-base font-semibold` (16px, 600).
- Body: reasoning text in `text-sm text-muted-foreground` (14px, 400).
- Icon: Lucide `Info` at 16px, `text-muted-foreground`, positioned inline before the "Insufficient evidence" label.
- Badge: "Insufficient evidence" using `Badge variant="secondary"` with `text-xs`.
- Confidence badge: always shows "Low" in the low-confidence color treatment.

**States:**

| State | Treatment |
|-------|-----------|
| Levenshtein failure reason | Reasoning text: value from `reasoning` field (e.g. "Evidence quote failed Levenshtein verification at 0.72 similarity (threshold: 0.85)") |
| Critic unsupported reason | Reasoning text: value from `reasoning` field (e.g. "Critic returned unsupported: quote does not appear verbatim in source") |
| All tiers exhausted reason | Reasoning text: value from `reasoning` field (e.g. "All extraction tiers exhausted without producing verifiable evidence") |

### 3. ConfidenceBadge

**Purpose:** Renders the confidence level (`high` / `medium` / `low`) with semantic color.

**Visual Treatment:**
- Extends existing `Badge` component. Does NOT create a new variant in badge.tsx -- uses `className` overrides.
- Size: `text-xs` (12px), `font-medium` (500).
- Rounded: `rounded-full` (matches existing badge default).
- Colors: per semantic color table above.

**Mapping:**

| Confidence | Label | Icon (optional) | Color Treatment |
|------------|-------|-----------------|-----------------|
| high | "High confidence" | Lucide `CheckCircle2` 12px | Green semantic |
| medium | "Medium confidence" | Lucide `AlertCircle` 12px | Amber semantic |
| low | "Low confidence" | Lucide `MinusCircle` 12px | Neutral muted |

### 4. CriticVerdictBadge

**Purpose:** Renders the critic pass verdict as an inline badge on the result card. Uses AI-accent styling to signal this is an AI-generated quality signal.

**Visual Treatment:**
- Small inline badge, positioned after the confidence badge with 8px gap.
- Size: `text-xs` (12px), `font-medium` (500).
- Uses `ai-surface` utility class for `supported` verdict.

**Mapping:**

| Verdict | Label | Color Treatment |
|---------|-------|-----------------|
| supported | "Verified" | AI-accent violet (`ai-surface` class) |
| unsupported | "Unverified" | Red semantic |
| partial | "Partially verified" | Amber semantic |
| timeout | "Review pending" | Neutral muted |
| undefined/null | Not rendered | -- |

## Copywriting Contract

| Element | Copy | i18n Key |
|---------|------|----------|
| Insufficient evidence label | "Insufficient evidence" | `extraction.insufficientEvidence` (already exists in en-US.json) |
| Insufficient evidence reasoning prefix | (no prefix -- render `reasoning` field verbatim) | -- |
| Evidence unavailable (fetch error) | "Evidence unavailable" | `extraction.evidenceUnavailable` |
| Evidence loading | (skeleton only, no text) | -- |
| Confidence: high | "High confidence" | `extraction.confidenceHigh` |
| Confidence: medium | "Medium confidence" | `extraction.confidenceMedium` |
| Confidence: low | "Low confidence" | `extraction.confidenceLow` |
| Critic: supported | "Verified" | `extraction.criticVerified` |
| Critic: unsupported | "Unverified" | `extraction.criticUnverified` |
| Critic: partial | "Partially verified" | `extraction.criticPartial` |
| Critic: timeout | "Review pending" | `extraction.criticTimeout` |
| View source action | "View in source" | `extraction.viewInSource` |

**Primary CTA:** None. This phase has no user-initiated actions. All components are passive display of extraction results.

**Empty state:** Not applicable. The `EvidenceQuote` component is only rendered when evidence data exists. The `InsufficientEvidenceCard` IS the empty/absent-evidence state.

**Error state:** Evidence fetch failures show inline "Evidence unavailable" text with `AlertCircle` icon. No toast, no modal, no retry button -- the extraction result card remains functional with answer and reasoning visible.

**Destructive actions:** None in this phase.

## Interaction Contract

### EvidenceQuote Click

| Property | Value |
|----------|-------|
| Trigger | Click anywhere on the quote block |
| Behavior | Navigate to paper source view with character range highlighted |
| Feedback | Hover: background opacity increases. Active: translateY(0) via `btn-hover` utility. |
| Accessibility | `role="link"`, `tabIndex={0}`, `onKeyDown` handles Enter/Space. `aria-label="View evidence in source at characters {start} to {end}"`. |

### Tooltip on CriticVerdictBadge

| Property | Value |
|----------|-------|
| Trigger | Hover or focus on badge |
| Content | Full verdict reason text from the critic pass |
| Delay | 300ms open, 0ms close |
| Component | Existing `Tooltip` / `TooltipTrigger` / `TooltipContent` from shadcn |

### Skeleton Loading

| Property | Value |
|----------|-------|
| Duration | Matches Convex query latency (typically <200ms for reactive subscriptions) |
| Shape | 3 lines: 100% width, 85% width, 60% width. Height: 14px each. Gap: 8px. |
| Animation | `animate-pulse` (Tailwind default, 2s duration) |
| Color | `bg-muted` |

## Accessibility

| Requirement | Implementation |
|-------------|---------------|
| WCAG AAA contrast (7:1) | All text colors verified against backgrounds in OKLCH space. Confidence badge foreground colors meet 7:1 on their respective backgrounds. |
| Reduced motion | `EvidenceQuote` hover transition respects `prefers-reduced-motion: reduce` -- use `motion-safe:transition-colors` instead of bare `transition`. |
| Screen reader | `EvidenceQuote`: `aria-label` describes the action. `InsufficientEvidenceCard`: `role="status"` with `aria-live="polite"`. Confidence and critic badges: text content is the accessible label (no icon-only badges). |
| Focus indicators | All interactive elements use `focus-visible:ring-[3px] focus-visible:ring-ring/50` per existing shadcn pattern. |
| Alt text | Icons use `aria-hidden="true"` -- adjacent text labels carry the meaning. |
