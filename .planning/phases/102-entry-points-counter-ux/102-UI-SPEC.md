## Progress Bar Visual States

The `<ExtractionCounter>` progress bar has exactly 3 visual states:

| State | Condition | Indicator class | Label class | Label copy |
|-------|-----------|-----------------|-------------|------------|
| Default | `ratio < 0.8` | (none -- inherits `bg-primary`) | (none -- label only) | `"{count} / {limit} papers"` |
| Warning | `0.8 <= ratio < 1.0` | `[&>[data-slot=progress-indicator]]:bg-amber-500 dark:[&>[data-slot=progress-indicator]]:bg-amber-400` | `text-amber-600 dark:text-amber-400` | `"Approaching basket limit"` |
| Full | `ratio >= 1.0` | `[&>[data-slot=progress-indicator]]:bg-destructive` | `text-destructive` | `"Basket limit reached"` |

Progress bar value is clamped: `Math.min(ratio * 100, 100)`.

The ratio MUST be computed as `count / limit` where `limit` comes from the `getExtractionLimit` reactive query, NOT hardcoded to 1000. Fallback when query is loading: `limit ?? 1000`.

Source: CONTEXT.md D-02, RESEARCH.md Pitfall 1

## AddToExtractionButton Visual States

The `<AddToExtractionButton>` has exactly 3 visual states:

| State | Condition | Icon | Button class | Tooltip copy (i18n key) |
|-------|-----------|------|-------------|------------------------|
| Default | Paper not in basket, basket not full | `Plus` (lucide-react) | `variant="ghost" size="icon"` with `h-8 w-8` | `extraction.addButton.add` = "Add to extraction basket" |
| In basket | `useExtractionBasketStore.has(normalizedId)` | `Check` (lucide-react) | `variant="ghost" size="icon"` with `h-8 w-8 text-primary` | `extraction.addButton.inBasket` = "Already in basket" |
| Cap reached | `papers.size >= limit` AND paper not already in basket | `Plus` (lucide-react, dimmed via disabled) | `variant="ghost" size="icon"` with `h-8 w-8`, `disabled={true}` | `extraction.addButton.basketFull` = "Basket full -- remove papers to continue" |

When in-basket, clicking toggles to remove (icon stays `Check`, tooltip changes to `extraction.addButton.remove` = "Remove from basket" during hover intent). The button acts as a toggle.

Button size is `h-8 w-8` (32px touch target) matching the existing icon button pattern in `LibraryItemActions` (`h-9 w-9` for the external link, `size="icon-xs"` which maps to `size-6` for the dropdown trigger). The `h-8 w-8` choice sits between these two existing sizes and provides a minimum 32px target for pointer devices. Mobile touch targets are covered by the full PaperCard tap area.

Source: CONTEXT.md D-04, D-05, D-06, RESEARCH.md Pattern 3

## Sidebar Badge Visual Contract

| Badge state | Condition | Rendering |
|-------------|-----------|-----------|
| Hidden | `basketCount === 0` or `basketCount === undefined` | No badge rendered |
| Collapsed (1-9) | `isCollapsed && basketCount > 0 && basketCount <= 9` | `absolute -top-1.5 -right-1.5 h-4 w-4` pill with orange gradient, white `text-[10px] font-bold`, number displayed |
| Collapsed (overflow) | `isCollapsed && basketCount > 9` | Same pill, displays "9+" |
| Expanded (active) | `!isCollapsed && isActive && basketCount > 0` | Inline `text-xs px-2 py-0.5 rounded-full font-medium` with orange gradient, white text |
| Expanded (inactive) | `!isCollapsed && !isActive && basketCount > 0` | Inline `text-xs px-2 py-0.5 rounded-full font-medium bg-muted text-muted-foreground` |
| Tooltip | Any collapsed state | Badge count included in tooltip label |

Animation on count change: Use existing `motion.span` with `initial={{ scale: 0.6, opacity: 0 }} animate={{ scale: 1, opacity: 1 }}` from the existing badge pattern at `app-sidebar.tsx:167-175`. No new animation presets needed. The `subtleSpring` from `lib/animation-config.ts` (`stiffness: 350, damping: 30, mass: 0.8`) is used for the expand/collapse transition, matching existing sidebar behavior.

Source: CONTEXT.md D-10, D-11, `app-sidebar.tsx` lines 140-185

Destructive actions: Not applicable -- this phase has no destructive actions. Removing a paper from the basket via the toggle button is a non-destructive undo-able action (paper can be re-added immediately).

## Interaction Contracts

### I-01: Add paper to basket

| Step | User action | System response |
|------|-------------|-----------------|
| 1 | Hovers AddToExtractionButton | Tooltip "Add to extraction basket" appears (delay 0ms per TooltipProvider default) |
| 2 | Clicks button | Paper added to basket store via `useAddToBasket.addToBasket()` |
| 3 | -- | Button icon morphs from Plus to Check; color changes to `text-primary` |
| 4 | -- | Sidebar badge count increments (reactive Zustand selector) |
| 5 | -- | If basket drawer is open, counter progress bar updates |

No page navigation occurs. No toast on single-paper add (only on batch truncation).

### I-02: Remove paper from basket via button

| Step | User action | System response |
|------|-------------|-----------------|
| 1 | Hovers in-basket AddToExtractionButton | Tooltip "Remove from basket" appears |
| 2 | Clicks button | Paper removed from basket store |
| 3 | -- | Button icon morphs from Check to Plus; color reverts from `text-primary` to default |
| 4 | -- | Sidebar badge count decrements; if count reaches 0, badge hides |

### I-03: Bulk paste exceeds capacity

| Step | User action | System response |
|------|-------------|-----------------|
| 1 | Pastes N OpenAlex IDs (where N > remaining capacity) | `useAddToBasket.addToBasket(inputs)` called with array |
| 2 | -- | First M entries added (M = remaining capacity), rest dropped ("first N fit" order) |
| 3 | -- | `toast.info()` fires: "Added {M} papers; {N-M} dropped -- basket limit reached" |
| 4 | -- | All mount points update reactively: counter, sidebar badge, all buttons |

### I-04: Basket reaches capacity

| Step | System state | Visual change |
|------|-------------|---------------|
| 1 | `papers.size >= limit` | Progress bar turns destructive (red) |
| 2 | -- | "Basket limit reached" label appears next to counter |
| 3 | -- | ALL AddToExtractionButton instances for papers NOT in basket become `disabled` |
| 4 | -- | Disabled buttons show tooltip "Basket full -- remove papers to continue" |
| 5 | -- | Buttons for papers already IN basket remain enabled (for removal) |

## Accessibility Contracts

| Requirement | Implementation |
|-------------|----------------|
| Progress bar ARIA | Radix `ProgressPrimitive.Root` auto-provides `role="progressbar"`, `aria-valuenow`, `aria-valuemin=0`, `aria-valuemax=100` |
| Button accessible name | Each AddToExtractionButton uses tooltip text as the accessible description. Button has `aria-label` matching the current state tooltip text |
| Disabled button semantics | `disabled={true}` on `<Button>` applies `disabled:pointer-events-none disabled:opacity-50` and prevents keyboard activation |
| Tooltip keyboard access | Radix TooltipTrigger requires focusable element; `<Button>` is natively focusable. Tooltip shows on Tab focus |
| Badge screen reader | Sidebar badge count is included in the NavItem tooltip for screen readers in collapsed mode. In expanded mode, the badge `<span>` is visible text |
| Color not sole indicator | Progress bar state (warning/full) is communicated via BOTH color AND text label ("Approaching basket limit" / "Basket limit reached") |
| Reduced motion | Sidebar badge uses `motion.span` which respects `prefers-reduced-motion` when `motion/react` is configured with the app's `LazyMotion` setup. Phase 105 audits this explicitly |

Source: WCAG AAA target from CLAUDE.md design principles
