<task type="auto">
  <name>Task 2: Add internal mutations and onComplete handler</name>
  <files>convex/screening/mutations.ts</files>
  <action>
Extend mutations.ts with internal mutations and the workpool onComplete handler. Add imports: `internalMutation` from `"../_generated/server"`, `internal` from `"../_generated/api"`, `screeningPool` from `"../workpool"`, `scorePaper` from `"./scoring"`, `MAX_SCREENING_PAPERS_PER_JOB` from `"../lib/queryBounds"`, `decodeQuestionResponseMap` from `"../../lib/ai/core/question-key-codec"`.

Add these internal mutations BELOW the existing public mutations:

1. **`updateJobStatus`** -- internalMutation with args `{ jobId: v.id("screeningJobs"), status: screeningJobStatusValidator }`, returns `v.null()`. Patches job with new status and `updatedAt: Date.now()`.

2. **`enqueueScreeningPaper`** -- internalMutation with args `{ resultId: v.id("screeningResults"), jobId: v.id("screeningJobs") }`, returns `v.null()`. Patches the result status to `"processing"`, then calls `screeningPool.enqueueAction(ctx, internal.screening.workpoolActions.screenPaperAction, { resultId, jobId }, { onComplete: internal.screening.mutations.handleScreeningComplete, context: { resultId, jobId } })`. Use default retry config from the pool.

3. **`saveQualifiedPaperToLibrary`** -- internalMutation with args `{ userId: v.id("users"), openalexId: v.string(), rating: v.number(), title: v.string(), authors: v.optional(v.string()), doi: v.optional(v.string()), abstract: v.optional(v.string()), publicationYear: v.optional(v.number()) }`, returns `v.id("libraryItems")`. Same upsert logic as `saveToLibrary` but uses `args.userId` directly (no auth). Build `searchableText` from title+abstract+authors. Query `libraryItems` by `by_user_openalexId` index. If exists, patch rating+searchableText+updatedAt and return existing._id. If new, insert full document with savedAt+updatedAt, then increment `user.libraryItemCount` counter (get user, patch with currentCount + 1).

4. **`addToCollectionInternal`** -- internalMutation with args `{ userId: v.id("users"), collectionId: v.id("collections"), libraryItemId: v.id("libraryItems") }`, returns `v.null()`. Same idempotent logic as `addToCollection` but no auth. Query `libraryItemCollections` by `by_collection_item` index. If exists, return null (no-op). Otherwise insert junction row with `userId, collectionId, libraryItemId, assignedAt: Date.now()`, then increment `collection.itemCount` counter.

5. **`finalizeScreeningJobIfDone`** -- internalMutation with args `{ jobId: v.id("screeningJobs") }`, returns `v.null()`. Gets job. If not found or status is terminal (completed/cancelled/failed/creditsExhausted), return null. Check if `job.processedPapers + job.failedPapers >= job.totalPapers`. If not done, return null. If done, patch job with `status: "completed", completedAt: Date.now(), updatedAt: Date.now()`.

6. **`handleScreeningComplete`** -- `screeningPool.defineOnComplete({...})` with context validator `v.object({ resultId: v.id("screeningResults"), jobId: v.id("screeningJobs") })`. Handler logic:

   - If `result.kind === "success"`:
     - Extract `returnValue` as `{ responses: Record<string, boolean | null>, confidence: number, usage: { inputTokens: number, outputTokens: number } }` (the return from the workpool action).
     - Load the job via `ctx.db.get(context.jobId)` to get `scoringConfig`, `targetCollectionId`, `userId`, and `questions`.
     - If job not found or job.status is terminal, skip processing.
     - The responses from AI use encoded question keys (because Convex requires ASCII-only keys). Use `decodeQuestionResponseMap` to decode the responses back to original question text keys. Then map the decoded responses to boolean answers keyed by question key: for each question in `job.questions`, look up the response by `question.question` text to get the boolean answer, and map to `{ [question.key]: answer }`. This creates the `answers: Record<string, boolean | null>` that `scorePaper` expects.
     - Call `scorePaper(answers, job.scoringConfig)` to get `{ score, stars, qualified }`.
     - Patch the screening result with: `status: "completed"`, `answers` (the mapped Record), `score`, `stars`, `qualified`, `confidence: data.confidence`, `updatedAt: Date.now()`.
     - If `qualified`:
       - Load the screening result to get paper metadata (title, abstract, authors, doi, publicationYear, openalexId).
       - Call `ctx.runMutation(internal.screening.mutations.saveQualifiedPaperToLibrary, { userId: job.userId, openalexId: result.openalexId, rating: stars, title: result.title, authors: result.authors?.join(", "), doi: result.doi, abstract: result.abstract, publicationYear: result.publicationYear })`. Note authors conversion: `v.array(v.string())` on screeningResults -> `v.string()` on libraryItems via `.join(", ")`.
       - If `job.targetCollectionId` is set, call `ctx.runMutation(internal.screening.mutations.addToCollectionInternal, { userId: job.userId, collectionId: job.targetCollectionId, libraryItemId })` where `libraryItemId` is returned from saveQualifiedPaperToLibrary.
       - Increment `job.qualifiedPapers` counter: `ctx.db.patch(context.jobId, { qualifiedPapers: (job.qualifiedPapers ?? 0) + 1, processedPapers: (job.processedPapers ?? 0) + 1, updatedAt: Date.now() })`.
     - If NOT qualified:
       - Just increment processedPapers: `ctx.db.patch(context.jobId, { processedPapers: (job.processedPapers ?? 0) + 1, updatedAt: Date.now() })`.
   - If `result.kind === "error"` or `result.kind === "canceled"`:
     - Patch result with `status: "failed"`, `updatedAt: Date.now()`.
     - Increment failedPapers: `ctx.db.patch(context.jobId, { failedPapers: (job.failedPapers ?? 0) + 1, updatedAt: Date.now() })`.
   - Finally (both success and failure paths): call `ctx.runMutation(internal.screening.mutations.finalizeScreeningJobIfDone, { jobId: context.jobId })`.

7. **`setJobWorkflowId`** -- internalMutation with args `{ jobId: v.id("screeningJobs"), workflowId: v.string() }`, returns `v.null()`. Patches job with workflowId. Needed by Plan 02 workflow to store the workflow ID for cancellation.

IMPORTANT: The `handleScreeningComplete` uses `defineOnComplete` which registers on the screening pool module. The returned mutation reference MUST be exported (not just defined internally). The extraction pattern exports `handleDownloadAndIndexComplete` directly -- follow the same pattern.

IMPORTANT: For the onComplete handler, load the job fresh from DB to get current counters (avoid stale reads with OCC). The pattern is: load job, compute new counter value, patch. Convex OCC will retry on conflict.
