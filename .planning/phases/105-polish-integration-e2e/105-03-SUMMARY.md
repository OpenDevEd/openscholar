## Decisions Made

- **Node/V8 runtime split** (Rule 3 blocking issue — see Deviations): the plan's sketch had a single `testing.ts` file exporting both an action and a mutation under `"use node"`. Convex rejects this (error: "Only actions can be defined in Node.js"). Split into two files: `testing.ts` (Node, action only) + `testingMutations.ts` (V8, mutation). The `internal.extraction.testingMutations.insertSeededJob` reference is used from the action via `ctx.runMutation`.
- **Schema-reality adaptations** (Rule 1 — plan sketch was approximate): adapted insert shapes to match actual `convex/schema.ts`. Key adjustments: extractionJobs no title field; tier `"auto"|"cheap"|"accurate"`; extractionResults uses questionId (not questionKey); confidence literal `"high"|"medium"|"low"`; flat evidence fields; parsingSource `"abstract_only"` (plan's `"api"` would fail validator); extractionPapers.doi is `v.optional(v.string())` so use `undefined` not `null`.
- **en-GB drift resolution: remove, don't propagate** (Rule 2 — missing critical for parity test to pass): the pre-existing `reportBuilder.showingRange` and `reportBuilder.filteredFrom` keys in en-GB had no counterparts in the other 5 locales AND were unreferenced in source code. Removed the two orphans from en-GB rather than adding 5 unnecessary translations. Aligns with CLAUDE.md rule 3 ("no legacy, no dead code, be thorough").
- **Defense-in-depth guard in mutation**: the `assertDevEnvironment()` helper is called from BOTH `seedCompletedJob` (action entry) AND `insertSeededJob` (mutation). If some future internal function bypasses the action and calls the mutation directly, the dev-gate still blocks production.
