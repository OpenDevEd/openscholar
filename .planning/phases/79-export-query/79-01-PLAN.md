   - job: `_id`, `status` (screeningJobStatusValidator), `questions` (v.array(screeningQuestionValidator)), `scoringConfig` (screeningScoringConfigValidator), `totalPapers`, `qualifiedPapers`, `createdAt`, `completedAt` (optional)
   - results array items: `openalexId`, `title`, `authors` (optional array), `publicationYear` (optional), `doi` (optional), `status` (screeningResultStatusValidator), `answers` (optional record of string to boolean|null), `score` (optional), `stars` (optional), `qualified` (optional)

3. **Handler:**
   - `getCurrentUser(ctx)` — return null if no user
   - `ctx.db.get(args.jobId)` — return null if no job or job.userId !== user._id
   - Query screeningResults with `.withIndex("by_job", (q) => q.eq("jobId", args.jobId)).take(MAX_SCREENING_PAPERS_PER_JOB)`
   - Map results to explicit shape (do NOT return raw documents, do NOT include aiMetadata per out-of-scope requirement)
   - Return `{ job: {...}, results: [...] }`

Important constraints:
- Do NOT filter by result status — return ALL results (pending, completed, failed, skipped) per EXP-05
- Do NOT include abstract or aiMetadata fields — out of scope per requirements
- Use `.take(MAX_SCREENING_PAPERS_PER_JOB)` not `.collect()` — bounded read
- Return null on auth/ownership failure, do NOT throw
