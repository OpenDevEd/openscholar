<objective>
Replace all `dangerouslySetInnerHTML` usage in `table-view.tsx` with an XSS-safe `HighlightedText` React component that uses text splitting instead of raw HTML injection.

Purpose: Eliminate the XSS attack vector where AI-generated answers or paper titles containing HTML are rendered unsanitized via `dangerouslySetInnerHTML`. React's built-in JSX text rendering auto-escapes all content, making the text splitting approach both simpler and safer than any sanitization library.

Output: A new `HighlightedText` component, updated `table-view.tsx` with zero `dangerouslySetInnerHTML` calls, and a test suite verifying XSS safety.
</objective>

  <behavior>
    - splitTextByQuery("hello world", "world") returns [{text: "hello ", isMatch: false}, {text: "world", isMatch: true}]
    - splitTextByQuery("no match here", "xyz") returns [{text: "no match here", isMatch: false}]
    - splitTextByQuery("text", "") returns [{text: "text", isMatch: false}]
    - splitTextByQuery("Case Test case", "case") returns segments with both "Case" and "case" as isMatch: true (case-insensitive)
    - splitTextByQuery('<script>alert("xss")</script>', "script") returns segments containing literal angle brackets as text, NOT executable HTML
    - When text contains HTML like "<b>bold</b>" and query is empty, the entire string is returned as non-matching text
    - Special regex characters in query (e.g., "test.js") are escaped and match literally
  </behavior>
  <action>
    1. Create `components/extraction/results-views/highlighted-text.tsx`:
       - Export `splitTextByQuery(text: string, query: string): Array<{ text: string; isMatch: boolean }>` pure function
       - If `query` is empty or whitespace-only, return `[{ text, isMatch: false }]`
       - Escape regex special chars in query: `query.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")`
       - Use `text.split(new RegExp(`(${escaped})`, 'gi'))` to get parts
       - Filter out empty strings from split result
       - For each part, determine isMatch by case-insensitive string comparison: `part.toLowerCase() === query.toLowerCase()` (do NOT reuse the global regex with `.test()` -- it has stateful `lastIndex` issues per research pitfall 1)
       - Export `HighlightedText({ text, query, className }: { text: string; query: string; className?: string })` React component
       - The component calls `splitTextByQuery`, renders a `<span>` wrapper, maps segments: matching segments get `<mark key={i} className="bg-yellow-200/50 dark:bg-yellow-500/30 rounded px-0.5">{seg.text}</mark>`, non-matching segments render as plain `{seg.text}`

    2. Create `tests/highlight-text.test.ts`:
       - Import `splitTextByQuery` from the component file
       - Test empty query returns full text unchanged
       - Test basic highlighting splits correctly
       - Test case-insensitive matching
       - Test multiple matches in one string
       - XSS test: text `<script>alert("xss")</script>` with query "script" -- segments contain literal `<script>` and `</script>` as text strings, `isMatch` correctly identifies "script" matches. Verify NO segment contains HTML that would be interpreted as a tag
       - XSS test: text `<img onerror=alert(1) src=x>` with empty query -- entire string returned as single non-matching segment
       - Test special regex characters in query: query `"test.js"` matches literal "test.js" not "testXjs"
       - Test query with HTML characters: query `<b>` in text `"use <b>bold</b>"` -- matches the literal `<b>` text
