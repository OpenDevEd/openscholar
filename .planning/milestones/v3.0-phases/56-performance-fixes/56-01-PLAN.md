<task type="auto">
  <name>Task 2: Implement batched subscription cron with circuit-breaker</name>
  <files>convex/maintenance/internal.ts, convex/subscriptions/internal.ts</files>
  <action>
Refactor `checkSubscriptionStatus` in `convex/maintenance/internal.ts` to process subscriptions in batches with a time-budget circuit-breaker and self-scheduling continuation.

**Approach:** The simplest approach (recommended by research) is to keep `listActiveSubscriptions` as-is (it already returns up to 1000 subs in one call) and implement batching purely in the action. The action fetches all subs once, then processes them in chunks of 50, checking elapsed time between chunks. If the circuit-breaker fires, it schedules a continuation with a `startIndex` cursor indicating where to resume.

**Implementation:**

1. Add args to `checkSubscriptionStatus`:
   ```typescript
   args: {
     startIndex: v.optional(v.number()),  // Index into subs array to resume from
     startedAt: v.optional(v.number()),   // Epoch ms when original run began
   },
   ```

2. In the handler:
   - Define constants: `CIRCUIT_BREAKER_MS = 45_000`, `BATCH_SIZE = 50`
   - Set `startedAt = args.startedAt ?? Date.now()`
   - Only call `expirePastDueSubscriptions` on the first invocation (when `startIndex` is undefined or 0)
   - Fetch all active subs via `listActiveSubscriptions` (already bounded to 1000)
   - Slice from `args.startIndex ?? 0`
   - Process subs in the loop, checking `Date.now() - startedAt > CIRCUIT_BREAKER_MS` after each sub
   - If circuit-breaker fires: schedule continuation with `ctx.scheduler.runAfter(0, internal.maintenance.internal.checkSubscriptionStatus, { startIndex: currentIndex, startedAt: Date.now() })` and return early. Note: reset `startedAt` to `Date.now()` on continuation so the next batch gets a fresh 45s budget.
   - The existing per-sub try/catch and Stripe API logic remains unchanged

3. Update the cron in `convex/crons.ts` if it passes args -- since the cron calls `checkSubscriptionStatus` with no args, and the new args are optional, the cron definition should NOT need changes. Verify by checking `convex/crons.ts`.

**Important:** The `listActiveSubscriptions` query is already bounded with `.take(1000)`. We do NOT need to modify it. The batching happens at the action level by processing the fetched array in chunks.
