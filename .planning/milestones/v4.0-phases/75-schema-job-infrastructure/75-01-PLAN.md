Create `convex/screening/validators.ts` with shared Convex validators:

1. `screeningQuestionValidator` - `v.object({ key: v.string(), question: v.string() })`. Note: the existing client-side ScreeningQuestion has `id` and `type` fields, but for bulk screening we only need `key` and `question` (the questions are boolean-only for screening). This is a snapshot embedded in the job record.

2. `screeningScoringRuleValidator` - `v.object({ questionKey: v.string(), yesPoints: v.number(), noPoints: v.number(), nullPoints: v.number() })`

3. `screeningScoringConfigValidator` - `v.object({ rules: v.array(screeningScoringRuleValidator), starThresholds: v.array(v.object({ minScore: v.number(), maxScore: v.number(), stars: v.number() })), minimumScore: v.optional(v.number()) })`

4. `screeningPaperInputValidator` - `v.object({ openalexId: v.string(), title: v.string(), abstract: v.optional(v.string()), authors: v.optional(v.array(v.string())), publicationYear: v.optional(v.number()), doi: v.optional(v.string()) })`

5. `screeningJobStatusValidator` - `v.union(v.literal("pending"), v.literal("processing"), v.literal("completed"), v.literal("cancelled"), v.literal("failed"), v.literal("creditsExhausted"))`

6. `screeningResultStatusValidator` - `v.union(v.literal("pending"), v.literal("processing"), v.literal("completed"), v.literal("failed"), v.literal("skipped"))`

Add to `convex/lib/queryBounds.ts`:
- `MAX_SCREENING_PAPERS_PER_JOB = 200`
- `MAX_SCREENING_JOBS_PER_USER = 500` (for listing query bounds)

All validators must be exported as named exports for use in schema.ts, mutations, and queries.

**convex/schema.ts** - Add two new tables after the existing tables, following the section comment pattern:

```
// ═══════════════════════════════════════════════════════════════
// SCREENING JOBS - bulk screening job records
// ═══════════════════════════════════════════════════════════════
```

`screeningJobs` table using the validators from `convex/screening/validators.ts`:
- `userId: v.id("users")`
- `status`: use `screeningJobStatusValidator` inline (copy the union, don't import -- Convex schema requires inline validators)
- `totalPapers: v.number()`, `processedPapers: v.number()`, `failedPapers: v.number()`, `qualifiedPapers: v.number()`
- `questions: v.array(v.object({ key: v.string(), question: v.string() }))`
- `scoringConfig`: inline the scoring config object shape matching `screeningScoringConfigValidator`
- `targetCollectionId: v.optional(v.id("collections"))`
- `workflowId: v.optional(v.string())`
- `createdAt: v.number()`, `updatedAt: v.number()`, `completedAt: v.optional(v.number())`
- Indexes: `.index("by_user", ["userId"])`, `.index("by_user_status", ["userId", "status"])`, `.index("by_workflow", ["workflowId"])`

`screeningResults` table:
- `jobId: v.id("screeningJobs")`
- `openalexId: v.string()`, `title: v.string()`, `abstract: v.optional(v.string())`, `authors: v.optional(v.array(v.string()))`, `publicationYear: v.optional(v.number())`, `doi: v.optional(v.string())`
- `status`: inline result status union (pending, processing, completed, failed, skipped)
- `answers: v.optional(v.record(v.string(), v.union(v.boolean(), v.null())))`
- `score: v.optional(v.number())`, `stars: v.optional(v.number())`, `qualified: v.optional(v.boolean())`
- `aiMetadata: v.optional(v.object({ reasoning: v.optional(v.string()), confidence: v.optional(v.number()), model: v.optional(v.string()), provider: v.optional(v.string()) }))`
- `creditsUsed: v.optional(v.number())`
- `savedToLibrary: v.optional(v.boolean())`, `libraryItemId: v.optional(v.id("libraryItems"))`
- `createdAt: v.number()`, `completedAt: v.optional(v.number())`, `errorMessage: v.optional(v.string())`
- Indexes: `.index("by_job", ["jobId"])`, `.index("by_job_status", ["jobId", "status"])`, `.index("by_job_openalexId", ["jobId", "openalexId"])`

**convex/lib/errors.ts** - Add screening error codes to the `ErrorCode` union type, before the closing semicolon:
- `"SCREENING_JOB_ALREADY_ACTIVE"` - user already has a pending/processing job
- `"SCREENING_JOB_NOT_FOUND"` - job ID not found or not owned by user
- `"SCREENING_JOB_NOT_CANCELLABLE"` - job is in terminal state (completed, failed, cancelled, creditsExhausted)

Group them under a `// Screening` comment like other groups.

**convex/workpool.ts** - Add a dedicated `screeningPool` export below `pdfProcessingPool`. Use `maxParallelism: 5` (screening is lighter than PDF extraction). Same retry config as pdfProcessingPool. Add a comment: `// For bulk screening - separate from extraction to avoid cross-cancellation on cancelAll()`.

IMPORTANT: The schema MUST use inline validator definitions, not imported validators. Convex schema requires validators to be defined inline. The `convex/screening/validators.ts` file is for use in mutations/queries args, NOT in schema.ts.
