The workflow's early-return guard checks job status at the start. Since we cannot easily call the workflow step directly in tests (it requires WorkflowManager context), test the guard EFFECT instead:
- Create a job in "cancelled" status
- Call `enqueueAllPapers` (the mutation that would be called by the workflow step)
- Verify it returns early (the terminal guard at enqueueAllPapers:161-166 already prevents enqueue for terminal jobs)
- Assert no papers changed status, no workpoolIds assigned

```typescript
it("enqueueAllPapers returns early when job is cancelled", async () => {
  const t = convexTest(schema);
  const user = await seedUser(t);
  const jobId = await seedExtractionJob(t, user._id, { status: "cancelled" });
  // Seed a pending paper
  await seedExtractionPaper(t, jobId, "oa:test1");

  // Call enqueueAllPapers -- should be a no-op for cancelled job
  await t.run(async (ctx) => {
    await ctx.db.patch(jobId, {}); // trigger to make test framework happy
  });

  // Since enqueueAllPapers is an internalMutation, call via t.mutation on internal ref
  await t.mutation(internal.extraction.mutations.enqueueAllPapers, { jobId });

  // Paper should still be pending (not enqueued)
  const papers = await t.run(async (ctx) => {
    return await ctx.db
      .query("extractionPapers")
      .withIndex("by_job", (q) => q.eq("jobId", jobId))
      .collect();
  });
  // enqueueAllPapers should have returned early -- papers unchanged
  expect(papers[0].status).toBe("pending");
  expect(papers[0].workpoolId).toBeUndefined();
});
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-93-08 | Information Disclosure | workpoolActions error logging | mitigate | Error messages truncated to 200 chars in console.error and 500 chars in DB persistence. No stack traces stored. No user PII in error paths. |
| T-93-09 | Denial of Service | Retryable error default | accept | Default-to-retryable for unknown errors means up to 3 attempts per paper. At maxAttempts: 3 with exponential backoff (2s, 4s, 8s), cost ceiling is 14 seconds per paper for unknown errors. Acceptable at MVP scale. |
| T-93-10 | Tampering | Error message in PDF text | mitigate | Error messages come from the catch block (HTTP responses, DOMException), not from PDF text content. PDF text is never directly used as an error message. |
</threat_model>
