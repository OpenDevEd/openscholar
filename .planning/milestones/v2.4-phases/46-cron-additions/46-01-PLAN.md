**Step 1: Add `cleanupExpiredOAuthTokens` to `convex/zotero/mutations.ts`**

Add the following `internalMutation` at the end of the file (after the `disconnect` mutation, before the closing of the file). This co-locates all token lifecycle operations (create in `storeRequestToken`, read in `getRequestToken`, cleanup here).

```typescript
/**
 * Cron: delete expired OAuth request tokens.
 * Tokens have a 10-minute TTL set during storeRequestToken.
 * This cleans up tokens from abandoned OAuth flows (user starts connect, never completes callback).
 */
export const cleanupExpiredOAuthTokens = internalMutation({
  args: {},
  returns: v.null(),
  handler: async (ctx) => {
    const now = Date.now();
    const allTokens = await ctx.db.query("zoteroOAuthTokens").collect();

    let deletedCount = 0;
    for (const token of allTokens) {
      if (token.expiresAt < now) {
        try {
          await ctx.db.delete(token._id);
          deletedCount++;
        } catch {
          // Token may have been deleted by getRequestToken or concurrent process.
          // Safe to ignore -- Convex OCC retries handle this gracefully.
        }
      }
    }

    if (deletedCount > 0) {
      console.log(`[cleanupExpiredOAuthTokens] Deleted ${deletedCount} expired token(s)`);
    }

    return null;
  },
});
```

Key design decisions (from RESEARCH.md):
- `.collect()` is used because the table is tiny (0-5 rows during active OAuth flows). No index on `expiresAt` needed.
- `try-catch` around individual deletes handles the concurrent deletion race with `getRequestToken` (which also deletes expired tokens it encounters).
- Logging only when `deletedCount > 0` to avoid noisy cron logs (the common case is 0 expired tokens).
