# Roadmap: v4.0 Bulk Screening & Auto-Rating

## Overview

v4.0 adds bulk background screening for up to 200 search results with user-defined scoring rules, automatic star ratings, and auto-save to library collections. The implementation reuses the proven extraction workflow pattern (workflow + workpool + credit-guard) and adds a pure-function scoring engine. Four phases deliver the feature: schema and job infrastructure, scoring engine, workflow processing with library integration, and the configuration dialog with progress UI.

## Phases

**Phase Numbering:** Continues from v3.2 (Phases 72-74). v4.0 starts at Phase 75.

- [ ] **Phase 75: Schema & Job Infrastructure** - Tables, job creation/cancellation mutations, credit verification, and reactive progress query
- [ ] **Phase 76: Scoring Engine & Rating Logic** - Pure scoring functions, per-question point rules, score-to-star threshold mapping, and minimum score filtering
- [ ] **Phase 77: Workflow Processing & Library Integration** - Background workflow+workpool pipeline, auto-save qualifying papers to library with computed rating, auto-assign to collection
- [ ] **Phase 78: Configuration Dialog & Progress UI** - Screen All button, configuration dialog with scoring/threshold/collection editors, cost estimate, progress tracking, and job history

## Phase Details

### Phase 75: Schema & Job Infrastructure
**Goal**: Users can create and cancel bulk screening jobs with credit verification, backed by persistent schema
**Depends on**: Nothing (first phase of v4.0)
**Requirements**: JOB-01, JOB-04, JOB-07
**Success Criteria** (what must be TRUE):
  1. A `screeningJobs` table exists with job state, scoring config, rating thresholds, progress counters, and proper indexes
  2. A `screeningResults` table exists with per-paper screening responses, computed score/rating, and library item reference
  3. User can start a bulk screening job that persists to the database (mutation creates job record with status "pending")
  4. System rejects job creation when user has insufficient credits (returns clear error before any processing starts)
  5. User can cancel a running screening job (status transitions to "cancelled", workpool processing stops, partial results are preserved)

### Phase 76: Scoring Engine & Rating Logic
**Goal**: Papers receive computed scores and star ratings based on user-defined rules
**Depends on**: Phase 75
**Requirements**: SCORE-01, SCORE-02, SCORE-03, SCORE-04, SCORE-05
**Success Criteria** (what must be TRUE):
  1. User can define point values per screening question for each answer type (yes/no/null each get independent +/- point values)
  2. System computes a total score per paper by summing per-question points based on AI screening responses
  3. User can define star rating thresholds that map score ranges to 0-5 stars (e.g., 0-2 = 1 star, 3-5 = 2 stars, etc.)
  4. System maps each paper's total score to a star rating using the user-defined thresholds (including edge cases: negative scores, all-null responses)
  5. Papers below a user-defined minimum score threshold are excluded from library saves

### Phase 77: Workflow Processing & Library Integration
**Goal**: Bulk screening runs in the background, processes papers through AI screening, and saves qualifying results to the user's library and collection
**Depends on**: Phase 75, Phase 76
**Requirements**: JOB-05, LIB-01, LIB-02, LIB-03
**Success Criteria** (what must be TRUE):
  1. Bulk screening processes papers in background via Convex workflow+workpool (user can close browser and papers continue processing)
  2. Per-paper failures do not block the batch (fail-soft: failed papers are recorded with error status, remaining papers continue)
  3. Qualifying papers (above minimum score threshold) are automatically saved to the user's library with the computed star rating
  4. Qualifying papers are automatically added to the user-selected collection (with idempotent membership -- no duplicates if paper already in collection)
  5. Credits are deducted per-batch with credit-guard protection (cancelled jobs stop billing immediately, with at most 1-batch race window)

### Phase 78: Configuration Dialog & Progress UI
**Goal**: Users can configure and launch bulk screening from the results page and track progress in real time
**Depends on**: Phase 75, Phase 76, Phase 77
**Requirements**: DIALOG-01, DIALOG-02, DIALOG-03, DIALOG-04, DIALOG-05, DIALOG-06, DIALOG-07, JOB-02, JOB-03, JOB-06, JOB-08
**Success Criteria** (what must be TRUE):
  1. "Screen All" button on the results page opens a configuration dialog showing the screening questions from the existing screening panel
  2. Dialog provides a scoring rules editor (per-question point values for yes/no/null) and a star rating threshold editor (score ranges mapped to stars)
  3. Dialog includes a collection picker with option to create a new collection inline
  4. Dialog displays paper count (capped at 200 with clear messaging if results exceed cap), estimated credit cost, and confirm/cancel buttons
  5. Dialog prevents dismissal during job submission (dismiss guards matching upgrade dialog pattern)
  6. User can view real-time progress of a running job (X/N papers screened, updated reactively)
  7. User can view a list of past bulk screening jobs showing status, paper count, and date
