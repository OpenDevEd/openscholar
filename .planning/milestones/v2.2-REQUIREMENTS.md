# Requirements: OpenAlex Count

**Defined:** 2026-03-01
**Core Value:** Reliable, well-tested academic search and AI extraction

## v2.2 Requirements

Requirements for Library UI Overhaul milestone. Each maps to roadmap phases.

### Layout & Responsive Design

- [x] **LAYOUT-01**: Library page uses two-column layout with filter sidebar on left and content area on right
- [x] **LAYOUT-02**: Filter sidebar is collapsible on desktop with toggle button and smooth animation
- [x] **LAYOUT-03**: Library page uses tab-based interface on mobile (Results/Filters tabs) matching search page pattern
- [x] **LAYOUT-04**: Sidebar is sticky on desktop so filters remain visible while scrolling content

### Filter Sidebar

- [x] **FLTR-01**: User can filter library items by rating using star buttons in sidebar
- [x] **FLTR-02**: User can filter library items by date saved (week/month/year presets) in sidebar
- [x] **FLTR-03**: User can filter library items by publication year range in sidebar
- [x] **FLTR-04**: User can filter library items by collection using dropdown in sidebar
- [x] **FLTR-05**: User can search within library items using text search in sidebar
- [x] **FLTR-06**: Active filter count badge displays on sidebar header
- [x] **FLTR-07**: User can clear all active filters with a single button
- [x] **FLTR-08**: All filter state persists in URL via nuqs (bookmarkable, survives reload)

### Display & Navigation

- [x] **DISP-01**: User can sort library items via dropdown (date saved, year, rating, title)
- [x] **DISP-02**: Sort options are disabled/hidden when text search is active (relevance ordering from search index)
- [x] **DISP-03**: Pagination displays result counts ("X-Y of Z papers") with prev/next navigation
- [x] **DISP-04**: Rating is visually displayed on each library item row and card
- [x] **DISP-05**: User can toggle between list and grid view modes

### Component Architecture (DRY)

- [x] **DRY-01**: SidebarLayout component generalizes two-column desktop + mobile tabs pattern for reuse across pages
- [x] **DRY-02**: FilterSidebar component provides generic sidebar chrome (title, collapse toggle, active count badge, clear button, content slot)
- [x] **DRY-03**: Search page refactored to use SidebarLayout + SearchFilterSidebar (replacing monolithic SearchSidebar)
- [x] **DRY-04**: Library page uses same SidebarLayout + LibraryFilterSidebar composition
- [x] **DRY-05**: All new shared components have full i18n support across 6 locales
- [x] **DRY-06**: FilterSection component reused by both search and library filter panels (no duplication)

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Nested/hierarchical collections | Flat collections more maintainable; nested trees confuse navigation and export |
| Infinite scroll | Pagination wins on predictability, accessibility, and mobile |
| Complex AND/OR/NOT filter logic | All filters apply as AND; advanced syntax deferred until demand materializes |
| Real-time multi-user sync | Page refresh sufficient for personal library; adds hidden complexity |
| AI-powered search or tagging | Requires LLM integration; v3+ scope |
| Smart collections (auto-grouping) | Requires continuous query engine; v3+ scope |
| Shared reading lists | Requires permission models; v3+ scope |
| Related papers discovery | Requires embedding similarity; v3+ scope |
