**CRED-02 -- Pagination fix in `convex/credits/actions.ts`:**

In `reconcileRecentPaidInvoicesFromStripeLogic`, replace the non-paginating invoice list call (around line 424-428):

```typescript
// BEFORE (broken for >100):
const invoices = await stripe.invoices.list({
  customer: stripeCustomerId,
  created: { gte: cutoffUnixSeconds },
  limit: 100,
});

const candidates = selectReconcileInvoiceCandidates({
  invoices: invoices.data,

```

Replace with auto-paginating `for await...of` loop with a safety cap:

```typescript
// AFTER (paginated with safety cap):
const MAX_INVOICES_PER_CUSTOMER = 500;
const allInvoiceData: StripeInvoiceReconcileLike[] = [];
for await (const invoice of stripe.invoices.list({
  customer: stripeCustomerId,
  created: { gte: cutoffUnixSeconds },
  limit: 100,
})) {
  allInvoiceData.push(invoice as unknown as StripeInvoiceReconcileLike);
  if (allInvoiceData.length >= MAX_INVOICES_PER_CUSTOMER) {
    console.warn(
      `[reconcileRecentPaidInvoices] Safety cap reached for customer ${stripeCustomerId}: ${MAX_INVOICES_PER_CUSTOMER} invoices. Some invoices may be skipped.`
    );
    break;
  }
}

const candidates = selectReconcileInvoiceCandidates({
  invoices: allInvoiceData,
  cutoffUnixSeconds,
});
```

The Stripe SDK's `list()` returns an `ApiList` object that supports `for await...of` iteration. The `limit: 100` controls page size, not total results. The SDK handles cursor pagination automatically via `has_more` + `starting_after`.

The `MAX_INVOICES_PER_CUSTOMER` safety cap (500) prevents unbounded iteration for edge-case customers. If hit, a warning is logged so it can be investigated. Per Claude's discretion.
