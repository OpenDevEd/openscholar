<objective>
Resolve N+1 sequential query patterns in the two extraction reporting helper functions by replacing sequential `for` loops with `Promise.all(papers.map(...))`.

Purpose: Both `loadJobDataForReporting` and `loadJobPapersAndResults` iterate papers sequentially, issuing 2+ database queries per paper. For a 100-paper job this produces 100-200+ sequential reads. `Promise.all` allows the Convex runtime to schedule all reads concurrently within the same transaction.

Output: Two refactored helper functions with identical return types and data shapes.
</objective>

Current code (lines 59-74):
```typescript
for (const paper of papers) {
  const [results, reviews] = await Promise.all([
    ctx.db.query("extractionResults")
      .withIndex("by_paper", (q) => q.eq("paperId", paper._id))
      .collect(),
    ctx.db.query("extractionResultReviews")
      .withIndex("by_paper", (q) => q.eq("paperId", paper._id))

  resultsByPaper.set(paper._id, results);
  for (const review of reviews) {
    reviewsByResult.set(review.resultId, review);
  }
}
```

Replace with:
```typescript
await Promise.all(papers.map(async (paper) => {
  const [results, reviews] = await Promise.all([
    ctx.db.query("extractionResults")
      .withIndex("by_paper", (q) => q.eq("paperId", paper._id))
      .collect(),
    ctx.db.query("extractionResultReviews")
      .withIndex("by_paper", (q) => q.eq("paperId", paper._id))
      .collect(),
  ]);
  resultsByPaper.set(paper._id, results);
  for (const review of reviews) {
    reviewsByResult.set(review.resultId, review);
  }
}));
```

The Maps `resultsByPaper` and `reviewsByResult` are declared OUTSIDE the `Promise.all` and populated as side effects inside each callback -- exactly as the original loop did. The return statement `{ questions, papers, resultsByPaper, reviewsByResult }` remains unchanged.
