# Roadmap: v2.4 Concerns Sweep

## Overview

The v2.4 Concerns Sweep fixes all tech debt, known bugs, and security concerns identified during the v2.3 codebase mapping. All 15 items are fixes to existing deployed code -- no new features, no new dependencies. The work is ordered by risk and dependency: schema migration first (gates all other schema changes), then cascade delete and workflow integrity (shared foundation for later phases), then type safety (highest effort, lowest urgency, requires incremental deployment), and finally cron additions (purely additive, low risk).

## Phases

**Phase Numbering:**
- Integer phases (43, 44, 45, 46): Planned milestone work
- Decimal phases (43.1, 43.2): Urgent insertions (marked with INSERTED)

- [ ] **Phase 43: Schema Migration & Quick Wins** - Encrypt and remove deprecated apiKey field, delete test page, fix placeholder email, document debug policy
- [ ] **Phase 44: Workflow & Deletion Integrity** - Cancel extraction actually stops processing, fix orphan diffs, surface diff truncation, extend GDPR user cleanup
- [ ] **Phase 45: Type Safety Sweep** - Typed extraction validators, typed migration steps, typed review metadata, remove getJobDetails cap
- [ ] **Phase 46: Cron Additions** - Automated cleanup of expired Zotero OAuth tokens

## Phase Details

### Phase 43: Schema Migration & Quick Wins
**Goal**: All plaintext API keys encrypted and removed from schema; dead code and placeholder values eliminated; debug endpoint policy documented
**Depends on**: Nothing (first phase in milestone)
**Requirements**: SEC-01, SEC-02, SEC-04, SEC-05, BUG-05
**Success Criteria** (what must be TRUE):
  1. Zero Zotero connections in the database still carry a plaintext `apiKey` field -- verified by dashboard query returning 0 rows
  2. The `apiKey` field no longer exists in `convex/schema.ts` and all `resolveZoteroApiKey` fallback code paths referencing it are removed
  3. Navigating to `/test-sidebar` returns a 404 -- the page no longer exists in the codebase
  4. The OpenAlex User-Agent header contains a real operational email address, not `admin@example.com`
  5. Every debug endpoint has inline JSDoc documenting its production policy and `requirePublicDebugEnabled()` gate
**Plans**: 2 plans

Plans:
- [ ] 43-01-PLAN.md -- Migrate and clear plaintext apiKey, remove deprecated field from schema and all fallback code (SEC-01, SEC-02)
- [ ] 43-02-PLAN.md -- Delete test-sidebar page, replace placeholder email, add JSDoc policy to debug endpoints (SEC-04, SEC-05, BUG-05)

### Phase 44: Workflow & Deletion Integrity
**Goal**: Extraction cancellation actually stops workflows and protects credits; deleted jobs leave no orphaned data; deleted users' extraction data is cleaned up
**Depends on**: Phase 43
**Requirements**: BUG-01, BUG-03, BUG-04, SEC-03
**Success Criteria** (what must be TRUE):
  1. Cancelling an extraction job calls `workflow.cancel()` and per-paper `pdfProcessingPool.cancel()`, and a status-check guard in the workpool action prevents credit deduction for papers processed after cancellation
  2. Deleting an extraction job also deletes all `extractionRunDiffs` where `baselineJobId` matches the deleted job -- no orphaned diff rows remain
  3. When `extractionRunDiffs.changes` exceeds the cap, the document includes `isTruncated: true` and `totalChanges` with the real count, and the UI surfaces this to the user
  4. Running `cleanupDeletedUsers` cascade-deletes extraction jobs, papers, results, evidence units, and Zotero connections for deleted users while preserving `creditTransactions` and other financial records
**Plans**: 2 plans

Plans:
- [ ] 44-01-PLAN.md -- Fix cancelExtraction to call workflow.cancel() and pdfProcessingPool.cancelAll() with credit-guard in workpool actions (BUG-01)
- [ ] 44-02-PLAN.md -- Fix orphan baseline diffs, add diff truncation metadata with UI banner, extend GDPR user cleanup (BUG-03, BUG-04, SEC-03)

### Phase 45: Type Safety Sweep
**Goal**: All extraction queries return typed validators instead of v.any(); all remaining any-casts in extraction and migration code replaced with proper types; getJobDetails returns all papers
**Depends on**: Phase 44
**Requirements**: TYPE-01, TYPE-02, TYPE-03, TYPE-04, BUG-02
**Success Criteria** (what must be TRUE):
  1. A shared `convex/extraction/validators.ts` file exists with typed validator objects for all extraction document shapes used in query returns
  2. All 7 extraction queries that previously used `v.any()` now use typed return validators from the shared module, deployed one at a time with no runtime errors in Convex logs
  3. `attachReviewMetadata` uses `Doc<"extractionResultReviews">` instead of `Map<string, any>` and `review: any`
  4. All 7 `migrateSearchHistoryState` version steps have typed input/output shapes
  5. `getJobDetails` returns all papers in a job (no `.take(100)` cap) -- a job with 150 papers shows all 150

### Phase 46: Cron Additions
**Goal**: Expired Zotero OAuth tokens are automatically cleaned up on a schedule
**Depends on**: Phase 44
**Requirements**: CRON-01
**Success Criteria** (what must be TRUE):

  2. The cron handles already-deleted tokens gracefully (try-catch per individual delete) and does not crash if another process deletes a token concurrently
