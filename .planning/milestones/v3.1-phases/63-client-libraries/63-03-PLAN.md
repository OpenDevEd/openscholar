**lib/ai/core/execute.ts (1 instance):**

Line 69: `} as any)` on the `generateObject` call.

The `as any` cast exists because the Vercel AI SDK's `generateObject` has complex generic constraints and the `experimental_repairText` and `providerOptions` fields may not match exactly.

The cleanest fix: Replace `as any` with a more specific approach. The issue is that `providerOptions: STANDARD_PROVIDER_OPTIONS` has a deeply-typed `as const` shape that may not match the SDK's `ProviderOptions` type exactly.

Option A (preferred): Cast only `providerOptions`:
```typescript
const result = await generateObject({
  model,
  schema,
  experimental_repairText: repairText,
  providerOptions: STANDARD_PROVIDER_OPTIONS as Record<string, Record<string, unknown>>,
  temperature,
  system: prompts.system,
  prompt: prompts.prompt,
})
```
The `ProviderOptions` type in the AI SDK is `Record<string, Record<string, unknown>>`. Casting `STANDARD_PROVIDER_OPTIONS` to this type is more specific than `as any` and matches the SDK's expected shape.

If that still causes a type error due to `schema` generic inference, use Option B:
Cast the entire options object to the expected parameter type:
```typescript
// Widen to satisfy generateObject's complex generic constraints
const result = await generateObject({
  model,
  schema,
  experimental_repairText: repairText,
  providerOptions: STANDARD_PROVIDER_OPTIONS as Record<string, Record<string, unknown>>,
  temperature,
  system: prompts.system,
  prompt: prompts.prompt,
} as Parameters<typeof generateObject>[0])
```

This casts to the actual parameter type of `generateObject` — far more specific than `any`.
