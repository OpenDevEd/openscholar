The Convex SDK's type inference doesn't propagate through generics easily.

Replace each `as any` with the more specific `as typeof query` cast pattern — but actually, the cleanest approach is to tell TypeScript to trust the types through a helper:

For `useProtectedQuery` and `useOptionalAuthQuery` (lines 56-58, 84-86):
- Replace `query as any` → keep `query` without a cast, but cast the entire call using a typed wrapper. Actually, the simplest type-safe approach: use `// eslint-disable-next-line @typescript-eslint/no-explicit-any` is NOT acceptable. Instead:
- Define a helper type at the top of the file:
  ```typescript
  // Convex useQuery/usePaginatedQuery require exact Query type matching.
  // Our wrappers accept FunctionReference<"query"> which is the base type.
  // We use this intentional widening at the Convex API boundary.
  type AnyQuery = FunctionReference<"query", "public" | "internal", Record<string, unknown>, unknown>;
  ```

- Then cast: `query as AnyQuery` and `args as Record<string, unknown>` — but this is still `as`. The real issue is that Convex's `useQuery` signature uses rest args.

The cleanest practical solution: The casts are at the Convex SDK type boundary. Replace `as any` with `as FunctionReference<"query", "public", Record<string, unknown>, unknown>` for `query`, and `shouldRun ? (args as Record<string, unknown>) : "skip"` for args. This is more specific than `any` and documents the actual type boundary.

Actually — the simplest correct fix: cast to the right Convex types.
- `query as any` → Use a local type alias and cast once per function:
  ```typescript
  // Widen to satisfy Convex's exact-match generic constraint
  const q = query as FunctionReference<"query">;
  const a = shouldRun ? args : "skip";
  const data = useQuery(q, a) as Query["_returnType"] | undefined;
  ```
  Wait — `FunctionReference<"query">` IS the type of `query` already, so the cast is redundant. The actual problem is that `useQuery` uses `OptionalRestArgsOrSkip<Query>` which doesn't align with how we call it.

Best approach: Replace `as any` with `as never`. The `never` type satisfies any parameter constraint while being more type-safe than `any` (it can't leak into other expressions). This is a well-known TypeScript pattern for satisfying generic constraints at API boundaries:
```typescript
const data = useQuery(
  query as never,
  shouldRun ? (args as never) : "skip",
) as Query["_returnType"] | undefined;
```
