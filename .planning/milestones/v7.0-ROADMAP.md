# Milestone v7.0: Extraction Workbench

**Status:** ✅ SHIPPED 2026-04-16
**Phases:** 98-105
**Total Plans:** 23

## Overview

Restore the pre-v6.0 results workbench (table/card/split views with highlighted citations), build a unified cross-source paper selector (library + collections + search results + manual IDs + Zotero) that stages selections across multiple origins into one job via a persistent selection basket, enforce a 1000-paper per-job hard limit that's displayed at every selection point and structured for future per-tier enforcement, revive the orphaned Zotero OAuth flow from `convex/zotero/**`, and close the v6.0 integration gaps (UI-01 ExtractionDialog orphan, EXTR-01 TierSelector orphan, PARSE-07 parsingSource badge, CRASH-02 bare useQuery).

**Critical path:** `98 → 99 → 100 → 102 → 103 → 104 → 105` (Phase 101 parallelizable).

## Phases

### Phase 98: Pre-flight & Hard-Limit Foundation

**Goal**: Ship the per-tier-ready paper-limit constants and prove that a 1000-paper extraction job's reactive query stays under Convex's 8 MB result-size cap before the bump lands in production.
**Depends on**: Nothing (first v7.0 phase; builds on v6.0 `extractionJobs` + `extractionResults` schema)
**Requirements**: LIM-01, LIM-02, LIM-03, GAP-04
**Plans**: 2 plans

Plans:

- [x] 98-01-PLAN.md — Constants + helper + reactive query (LIM-01, LIM-02, LIM-03)
- [x] 98-02-PLAN.md — Call-site rewiring + payload benchmark (LIM-01, GAP-04)

**Details:**
Bumped `MAX_EXTRACTION_PAPERS_PER_JOB` 200→1000 via `Math.max` on `EXTRACTION_LIMITS_BY_TIER`; split internal `MAX_EXTRACTION_RESULTS_QUERY` (10,000) from user cap. Created `getExtractionLimitForUser(ctx)` helper in `convex/lib/extractionLimit.ts` and reactive `getExtractionLimit` query in `convex/extraction/queries.ts` routing through `resolveEffectivePlan`. Benchmark confirmed typical 1000-paper payload is 3.97 MB (under 5 MB target) and worst-case 10.31 MB (under Convex 16 MiB hard cap); pagination migration not needed.

## Milestone Summary

**Key Decisions:**

- Per-tier limit map (`EXTRACTION_LIMITS_BY_TIER`) as single source of truth; `MAX_EXTRACTION_PAPERS_PER_JOB` derived via `Math.max`
- `MAX_EXTRACTION_RESULTS_QUERY` (10000) decoupled from user-facing paper limit for internal `.take()` bounds
- Batch seeding in benchmark: 50 papers per txn for papers, 10 papers per txn for results (convex-test transaction limits)
- Worst-case benchmark at 10.31 MB asserts against 16 MiB Convex hard cap, not 5 MB target
- sessionStorage (not localStorage) for basket — clear only on successful job creation
- `normalizeOpenAlexId` utility handles 3 formats (`W123`, `https://openalex.org/W123`, `openalex:W123`)
- TierSelector fix is ~5 edits, NO migration — new rows only (legacy null-coalesces to `auto`)
- `@tanstack/react-table@^8.21.3` is the ONLY net-new runtime dep for this milestone
- Re-added shadcn `<Table />` primitive; rejected shadcn `data-table` block (monolithic — fights 4-view architecture)
- `@tanstack/react-virtual@^3.13.23` for card view only; table does NOT virtualize
- Highlighted-citation demoted from 4th view to drawer pattern (not all parsing sources are PDFs)
- Zotero stays on OAuth 1.0a (verified 2025-09-24); `zotero-api-client` rejected (API-key only)
- React 19 `useDeferredValue` for full-text search debounce in workbench
- ESLint 9 flat config: two separate config objects with progressively more-specific globs
- `test:ci` prepends lint (lint → test → build → e2e:auth) to fail fast before 5-min build step
- Next.js 16 removed `next lint` command; `eslint .` direct invocation
