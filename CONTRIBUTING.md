# Contributing to Openscholar

Thanks for helping. Each repository's README says how to run it.

## Before you start

For anything larger than a small fix, open an issue first so we can agree on the approach before you write the code.

## Making a change

1. Fork the repository and create a branch from the default branch (`dev` in openscholar, `main` in evidence-community).
2. Keep one change per pull request.
3. Write commit messages with a conventional prefix: `feat`, `fix`, `refactor`, `test`, `chore`, `docs`, `perf` or `style`. For example: `fix(search): keep the filter when the page reloads`.
4. Run the tests and checks for what you changed before you push. Each README lists the commands.
5. Open a pull request that says what changed and how you checked it. Link the issue it closes.

The checks on a pull request from a fork wait until a maintainer approves them, because they run on our own machines.
